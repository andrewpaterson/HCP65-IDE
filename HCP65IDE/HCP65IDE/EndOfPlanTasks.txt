a. Find duplicates: "Look for duplicates of selected text / function"
--------------------------------------------------------------------

What the user asked for (question 37, RefactoringQuestions.txt): a feature of its own, as IntelliJ's Locate
Duplicates: for the selected text, or the function at the caret, find the places in the solution that are the same
code, the comparison not minding what the variables are called, and list them (in the Find window, as Find Usages
lists, each one opened by a click).

What there is to build on: Extract Method already finds duplicates of its selection, in its own file only:
CIDEExtractMethod::FindDuplicates, IsDuplicate and ChooseDuplicates (IDEExtractMethod.h/.cpp).  It compares token
for token, with each local variable of the selection allowed to be a different one at the duplicate (consistently).
The new feature needs: the whole solution (each project's files, parsed with CIDERefactorUnit; the index's file
list is CIDECodeModel::NumProjectFiles/GetProjectFile); a whole function as the thing looked for (its body, its
parameters free like locals); statements that are the same sequence anywhere in a body, not only a whole body;
and a result list.  Find Usages' window (IDEFindUsages*) is where results are shown elsewhere.

Questions to ask the user before building: the menu and key (IntelliJ has no default key; Code, Locate Duplicates
is its menu); whether a match must be whole statements or can be part of an expression; how small a duplicate is
worth listing; whether literals must match.

The user's answers (2026-11-16):
  1. "Find Duplicates..." on the Edit menu, after Find in Files, on Control+Alt+Shift+D.
  2. Expressions too, as IntelliJ: a selected expression matches the same expression inside any statement (x * x + y
     * y is found in d = sqrt(a * a + b * b);), and a run of statements matches a run of statements.
  3. A selection is searched for whole.  For the function at the caret, copies of its whole body are listed first,
     then runs of its statements found elsewhere, longest first.  The smallest run listed is a Settings value,
     defaulting to 3 statements and 20 tokens.
  4. Literals must match by default.  A check box in the Find Duplicates dialog, remembered in Settings, lets
     literals of the same kind differ (number with number, string with string), as IntelliJ's anonymize literals.


b. Every getter: const, and where it is written
-----------------------------------------------

What the user asked for (question 44): a getter is declared in the class and defined on one line at the bottom of
the class's .cpp, where the one-line functions are ("int32 CListContainer::GetSelected(void) { return miSelected; }"),
and it is const.  "There is a pattern for it, not kept to everywhere": all the getters there are need looking at,
in all of the user's code (CommonLibraries, HCP65-IDE, HCP65, LogiCim).  Encapsulate Field writes new ones so
already (2026-11-15); the old ones are this task.

How: find the getters (a member function named Get..., Is..., Has..., that takes nothing and returns a member, or
something worked out from members without changing them).  For each, make it const with the IDE's own Make Member
Function const (CIDEMemberQualifier; it changes its overrides with it, and refuses what changes the object), and
move a one-line definition written in the class out to the bottom of the .cpp (Move Definition out of Class,
CIDEDefinitions), but in a class template or a class with no .cpp, where it stays in the class.

Careful: on 2026-11-07 a bulk change of Ptr<> and CPointer parameters to const& and of getters to return references
was made and reverted (aliasing; it exposed a write-through bug, since fixed).  This task is const on the function
only: don't change what a getter returns.  A getter that returns a non-const pointer or reference into the object
(&mcThing) can't simply be const: list those for the user instead.  Do it a library at a time, build and run its
tests (the 23 suites and build-only projects in the memory's test sweep) after each, and commit each.
