    banner, and leaves "typedef CTankTemplate<CGauge> CTank;" after them.  A class that is forward declared
    somewhere ("class CTank;") is refused, because a typedef can't be declared that way: most of your classes are
    forward declared.  Should it rewrite those forward declarations instead (to the template's and the typedef), or
    is the typedef not what you want at all, the uses of CTank becoming CTankTemplate<CGauge> everywhere?
    Answered 2026-11-15: neither: the class's old name is kept by a class that derives from the template and
    adds nothing but its constructors, "class CTank : public CTankTemplate<CGauge> {};", so every "class CTank;"
    stays as it is and a class declared ahead is no longer refused.  And the compiler is to warn where the
    template's instance is named directly ("CTankTemplate<CGauge> cTank;": use CTank).  The rule is inferred, with
    no new syntax: a class whose only base is a template's instance and whose body is empty but for constructors
    is that instance's name; no warning in that class's own base list, in the template's own code, or for an
    instance that has no such class; and only where the class can be seen from the use.  To do: Extract Template
    Parameter on a class, and the warning in CppCompilerLib.
