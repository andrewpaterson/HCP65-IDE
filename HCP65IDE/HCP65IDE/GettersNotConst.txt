The getters task b couldn't make const (EndOfPlanTasks.txt, b)
================================================================

Each library's getters were made const where the compiler allows it.  These are the ones it doesn't, by why, each
with the first error (its file and line as they were then).  b doesn't change what a getter returns, so a getter that
hands out a writable pointer or reference into its object stays as it is: they are yours to decide.

  - Hands out a writable pointer into its object: it returns &mcThing, an array of its own, or what a member's
    non-const function returns (most often CChars::Text's char*), C2440 and C2663.
  - Calls something of its object's that isn't const: another function that changes the object, or one that
    hands out a pointer (an array's Get(i), a list's GetHead), C2662.
  - Takes the address of a Ptr<> member, (CPins*)&mpPins: Ptr<>'s operator& (the address of what it points to) isn't
    const, so in a const getter &mpPins is the Ptr's own address, which the cast takes with no error.  Kept back
    without asking the compiler (found when TestMicroprocessorLib crashed).  Ptr<> keeps its operator& as it is: a
    const one was tried before and skipped the copy constructor's memory management (the user, 2026-11-17).
  - Other: anything else the compiler said.
